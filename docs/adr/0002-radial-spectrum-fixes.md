# ADR 0002: 円環スペクトラム (リング) のはみ出し・コントラスト不足を修正

- ステータス: 採用
- 日付: 2026-08-25

## 背景

`docs/adr/0001-radial-spectrum-visual.md` で追加した `RadialSpectrumCanvas` を
マージ後にレビューしたところ、実装は健全だったが 2 点の不具合があった。

### 1. チューニングパネルの上限同士を組み合わせるとバーが画面端で切れる

`RadialSettings` は `innerRadiusRatio` (最大 0.6) と `barLengthRatio` (最大 0.5) を
互いに独立したスライダーとしてチューニングパネルに出している。

`RadialSpectrumCanvas.body` はこれらを単純に掛け合わせてバーの外周半径を決めていたため、
たとえば内周比 0.6 + バー長比 0.5 という組み合わせだけで合計が 1.0 を超え、
`ringDeform` (内周の押し出し) や `pulseDepth` (拍による膨らみ) が加わるとさらに超過する。
`Canvas` は自身の矩形でコンテンツを clip するので、この組み合わせでは
バーの先端がキャンバスの外へはみ出して見た目がぶつ切りになっていた。

### 2. 「鳴っていない帯域は黒背景へ沈む」はずが、常時そこそこ明るいリングに見える

`RadialSpectrumCanvas.barColor` の明度は `0.4 + 0.6 * level` で計算していた。
コメントには「鳴っていない帯域は黒背景へ沈む」と書いていたが、無音 (`level = 0`) でも
明度 0.4 が残るため、実際には全帯域が常時それなりの明るさで点灯しているように見え、
「鳴っている帯域だけが発光する」という参考デザインのコントラストが出ていなかった。
これは 0001 で解決したかった「背景の主張が強すぎてバー表現の影響力が落ちる」問題を、
今度はリング自身の内側で再現してしまっていた形になる。

## 決定

### 1. バー最大長を、外周がキャンバス半径を超えないよう逆算して絞る

`RadialSpectrumCanvas.clampedBarLength(unit:baseRadius:requestedLength:ringDeform:)` を
純関数として追加した。外周の最大到達点は `baseRadius + length * (1 + ringDeform)` なので、
これが `unit` (キャンバス半径) を超えないよう `requestedLength` を上から抑える。

`innerRadiusRatio` / `barLengthRatio` のスライダー側の範囲はそのまま残している。
組み合わせ上限をスライダー側で狭めるより、「どんな組み合わせでも画面内に収まる」ことを
描画側で保証するほうが、パラメータ間の関係をユーザーが意識しなくて済む。

### 2. 明度の下限を下げてコントラストを出す

明度の式を `0.12 + 0.88 * level` に変更した。無音時の下限を 0.4 → 0.12 まで下げることで、
鳴っていない帯域は黒背景へ大きく沈み、鳴っている帯域との明るさの差がはっきり出るようにした。

完全な 0 にはしていない。`RadialSpectrumCanvas.endpoints` は無音時でも 2pt の点を
最小長として残す設計 (「完全に消えると輪郭が読めない」) なので、その点が実際に
視認できる最低限の明るさとして 0.12 を残した。

## 影響

- `RadialSpectrumCanvas` の見た目のみが変わる。`SpectrumCanvas` / 波形 / 色決定ロジックは無改修。
- `clampedBarLength` を単体テスト可能な純関数として切り出したので、
  スライダーの上限同士の組み合わせ (0.6 + 0.5 のケース) を含めて検証できる。
- 既存の `RadialSpectrumCanvasTests` の色・配置テストは値の範囲だけを見ているため、
  明度下限の変更による影響は受けない。
